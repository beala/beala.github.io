The flasher itself is the official one, unchanged. Erase images and bootloaders are copied from flasher.meshcore.io, so those are the same files.

Because these builds track dev, they get upstream's newest work before it's released, including its bugs. If something breaks, flash an older build from the version list, or the official firmware from flasher.meshcore.io.

What's different from mainline firmware

All boards

Packet parser security fixes. Neil Alexander's fixes from meshcore-dev/MeshCore#3521, not yet merged upstream. Malformed or truncated packets from the air could make the firmware read past the end of buffers or use stale memory; the parser now rejects them. Covers empty and short frames, partial encrypted payloads, oversized advert data, bad TRACE and CONTROL packets, and ACK overflows. One addition on top: packets with a newer, unsupported protocol version are dropped instead of being handled as version 1. beala/pr-3521

Heltec T1 and T1000-E

Buzzer off. The companion buzzer is disabled on both. Status LED off on the T1000-E. beala/custom

MeshTracker X1 (LR2021 radio)

These change the LR2021 driver, so they only affect the X1 on this site.

  • Full transmit power. RadioLib's power table for the LR2021 stops rising at about 14 dBm, whatever you set. This uses Semtech's reference table, so settings up to 22 dBm give the power they say. beala/fix-lr2021-pa-table
  • Semtech firmware patch. Semtech says to load a patch into the radio after every reset; RadioLib never does. It's now loaded at boot. beala/lr2021-pram-patch
  • AGC reset fix. With agc.reset.interval turned on, the radio was left asleep after each reset: packets were missed and queued messages didn't send. It now wakes and recalibrates properly. beala/fix-lr2021-agc-reset
  • Correct boosted-gain status. The boot log always said RX boosted gain was off, even when it was on. beala/fix-lr2021-rx-boost-status
  • SIMO power supply. The radio runs from its built-in DC-DC converter, which uses less current. Not yet confirmed on hardware; if your X1 can't transmit or receive on this build, flash an older one and let me know. beala/lr2021-simo-flag, beala/x1-simo
  • Radio diagnostics. The two commands below, plus transmit fault logging in debug builds. beala/lr2021-tx-fault-log, beala/lr2021-rx-gain-step, beala/lr2021-diagnostics

New commands (MeshTracker X1)

Send these from the companion app's command line (or any client that can run companion CLI commands). Other radios reply Unknown command.

get radio.faults

Transmits that went wrong since boot, newest first (up to 8), with how long ago each was.

> 3 since boot: 12s OCP; 95s ERR=0004; 300s NODONE
FlagMeaning
NODONEThe transmit didn't finish
OCPThe power amplifier hit its over-current or over-voltage limit
ERR=xxxxThe chip reported an error (its error register in hex; 0004 is a PLL lock failure)
CMDThe chip rejected a command
TIMEOUT, EOLThe chip's timeout and end-of-life signals

With no faults: > no TX faults since boot

get radio.agc

The receiver gain step the radio picked for each of the last packets, with their signal strength, SNR and age, newest first.

> G13 -112dBm -6.5dB 4s; G9 -87dBm 8.0dB 31s

Higher gain steps mean the radio amplified a weaker signal. Useful for spotting a receiver that's being overloaded by a nearby transmitter (low gain steps on weak packets). Before anything is received: > no packets received yet

How the builds are made

Every 30 minutes a GitHub workflow in beala/MeshCore rebuilds the beala/integration branch from scratch: upstream dev with each branch above merged on top. If the result changed, it builds all boards in parallel and publishes a release tagged beala-<commit>. This site checks for new releases every 15 minutes and republishes.

Each change lives on its own branch so it can also be sent upstream. When upstream merges one, it drops out of these builds by itself. The release notes list exactly which branches went into each build, with a link to the full diff against upstream.
